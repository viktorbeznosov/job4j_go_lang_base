2. Прямое преобразование большого int64 в int16 не проверяет диапазон
   Потому что в Go приведение типов (T(x)) — это не проверяемая операция, а низкоуровневое переинтерпретирование битов. Спецификация языка прямо говорит: при преобразовании между целочисленными типами значение усекается до разрядности целевого типа, и никакой ошибки не возникает.
3. Почему value receiver не подходит для Deposit/Withdraw: при вызове value receiver Go делает неявную копию acc в переменную a. Изменение a.Balance затрагивает только эту копию, оригинал остаётся прежним. Метод «отработал без ошибки», но баланс не изменился — тихая логическая ошибка.
4. Почему указатель не делает тип потокобезопасным
   Указатель решает совсем другую задачу — «изменения видны вызывающему». Он не решает задачу «несколько горутин одновременно меняют одно и то же».
